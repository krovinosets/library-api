# Library API — домашнее задание №3

Готовый contract-first проект OpenAPI 3.1 для библиотеки. Он описывает поведение API, но не содержит backend и не заявляет, что mock уже запущен.

## Файлы

```text
library-api/
├── openapi.yaml
├── STYLE.md
├── REVIEW.md
└── README.md
```

- `openapi.yaml`: 16 операций, схемы, фильтры, сортировка, пагинация, ошибки и политика Idempotency-Key.
- `STYLE.md`: 10 конкретных правил API.
- `REVIEW.md`: саморевью по пунктам 32–35 материалов урока и по рубрикатору.
- `README.md`: навигация, проверки, примеры и бонус — таблица совместимости v2.

## Базовый URL и операции

`servers.url`: `http://localhost:4010/v1/`. Это адрес локальной реализации/mock, а не уже запущенный сервис. `/v1` не дублируется в paths.

| Ресурс | Список | Создание | По ID | Замена | Частичное изменение | Удаление/возврат |
| --- | --- | --- | --- | --- | --- | --- |
| Books | GET /books | POST /books | GET /books/{id} | PUT /books/{id} | PATCH /books/{id} | DELETE /books/{id} |
| Readers | GET /readers | POST /readers | GET /readers/{id} | PUT /readers/{id} | PATCH /readers/{id} | DELETE /readers/{id} |
| Loans | GET /loans | POST /loans | GET /loans/{id} | — | — | POST /loans/{id}/return |

## Выбранная семантика

- Все ID — UUID. ISBN — ISBN-13 из 13 цифр, без разделителей, с серверной проверкой контрольной суммы; уникален среди неудалённых книг. Email уникален без учёта регистра среди неудалённых читателей.
- Серверные поля не принимаются в JSON тела; неизвестные поля запрещены. available_copies = total_copies − активные выдачи книги. Фонд может быть нулевым.
- Активная выдача: returned_at=null, даже если она просрочена. Лимит — 5 на читателя. due_date новой выдачи > сегодня UTC; overdue — активная выдача с due_date < сегодня UTC, не <=.
- Полная замена PUT требует все изменяемые поля и не создаёт новый ресурс. PATCH — непустой JSON-объект, не JSON Patch/Merge Patch; null для изменяемых полей запрещён.
- Возврат без тела; повторный возврат — 200 с исходным returned_at, не повторное изменение фонда.
- Удаление Books/Readers — логическое; с активными выдачами запрещено. История Loan сохраняется; GET удалённого ресурса — 404. Это не обещание физического удаления персональных данных.
- Все timestamp выдаются в UTC с Z; фильтры timestamp принимают RFC 3339 с часовым поясом. Динамические правила и транзакции реализует сервер, не JSON Schema.
- Пагинация limit/offset: default 20/0, max 100/1000000; ответ data + pagination(limit, offset, total, has_more). Нет общего снимка между разными запросами страниц.
- Фильтры/query — kebab-case, JSON — snake_case. sort — один токен, `-` означает DESC; вторичный ключ id ASC. Неизвестные/повторные query-параметры — 400.
- 409 — конфликт состояния/уникальности/идемпотентности; 422 — значения/структура JSON или due_date не в будущем; 400 — синтаксис/параметры; 415 — Content-Type не JSON. Все прикладные ошибки используют ErrorResponse.

## Idempotency-Key

Подробная нормативная политика находится в description `POST /loans`; кратко:

| Ситуация | Ответ/поведение |
| --- | --- |
| Ключ отсутствует или не UUID | 400 INVALID_REQUEST; нет резервирования |
| Новое валидное тело и ключ | Атомарное резервирование, проверки, создание Loan, 201 + Location |
| Тот же ключ и семантически то же JSON-тело, запрос завершён | Полный replay исходного статуса, байтов тела и всех HTTP-заголовков, включая Location, X-Request-Id и Date при наличии |
| То же ключевое значение, другое валидное тело | 409 IDEMPOTENCY_MISMATCH; не изменяет исходный результат |
| Конкурентный тот же ключ и тело, первый запрос ещё выполняется | 409 CONFLICT, issue=idempotency_in_progress, Retry-After: 1; нового Loan нет |
| Прикладная ошибка после резервирования | Завершённые 404/409/422 сохраняются и повторяются так же, как 201 |
| Синтаксическая/статическая валидация до резервирования | 400/415/422 не резервируют ключ |
| Прошло 24 часа с атомарного завершения | Ключ считается новым; безопасный replay уже не гарантируется |
| Сбой исполнителя при in-progress | Запись не истекает по TTL завершённых ответов; требуется восстановление без дублирования выдачи |

Scope: POST + `/v1/loans` + UUID ключа (без учёта регистра), глобально для учебного API без авторизации. Fingerprint: SHA-256 канонического JSON с сортировкой ключей и без незначащих пробелов; UUID в теле не нормализуется, Unicode не нормализуется. Перестановка полей/пробелы не дают mismatch; изменение значения даёт mismatch. Повтор завершённого ответа предшествует динамической проверке due_date: старый успех остаётся replay даже после наступления срока.

TTL не продлевается повторами; на границе completed_at + 24h ключ истёк. При разных ключах транзакционные ограничения всё равно запрещают перерасход экземпляров и превышение пяти выдач.

## Проверки и примеры

В подготовленном проекте выполнены: разбор YAML, проверка всех внутренних `$ref`, уникальности operationId, полноты операций, проверка компонентных схем как JSON Schema 2020-12, валидация всех JSON examples с format-проверками и негативные schema-тесты. Полноценный OpenAPI lint/генерация SDK, работа mock и транзакционные тесты сервера в этой среде не запускались.

Локальная проверка установленным Redocly CLI:

```bash
cd library-api
npx @redocly/cli lint openapi.yaml
```

CLI может дать дополнительные style-рекомендации (например, contact/license/security): отсутствие авторизации здесь сознательно задокументировано. Версию CLI следует закрепить в CI после проверки её поддержки OpenAPI 3.1.

Ниже запросы к будущей реализации или отдельно запущенному mock. Они не являются доказательством запуска сервера. Дата для создания рассчитывается относительно текущей даты UTC; существующие ID книги/читателя необходимо подставить из POST /books и POST /readers.

```bash
curl -i 'http://localhost:4010/v1/books?available=true&sort=-published-year&limit=20&offset=0'
curl -i 'http://localhost:4010/v1/loans?status=overdue&sort=due-date&limit=20'
```

Создание выдачи (нужны установленный Python 3 и реальные ID):

```bash
BOOK_ID='11111111-1111-4111-8111-111111111111'
READER_ID='22222222-2222-4222-8222-222222222222'
KEY=$(python3 -c 'import uuid; print(uuid.uuid4())')
DUE_DATE=$(python3 -c 'from datetime import datetime, timezone, timedelta; print((datetime.now(timezone.utc).date()+timedelta(days=14)).isoformat())')
BODY=$(printf '{"book_id":"%s","reader_id":"%s","due_date":"%s"}' "$BOOK_ID" "$READER_ID" "$DUE_DATE")
curl -i -X POST 'http://localhost:4010/v1/loans'   -H 'Content-Type: application/json'   -H "Idempotency-Key: $KEY"   --data "$BODY"
```

Повторите последний curl с неизменными KEY и BODY в течение 24 часов после завершения — ожидается полный replay. Не генерируйте новый KEY при транспортном повторе. Для проверки mismatch измените due_date, сохранив KEY. Для возврата выполните `curl -i -X POST 'http://localhost:4010/v1/loans/<полученный-id>/return'` без `--data`.

Статические examples используют даты 2030 года как иллюстрацию. Перед живым POST выбирайте due_date относительно часов сервера; example не отменяет динамическое правило. Mock, построенный только на OpenAPI, не доказывает работу лимитов, TTL, вычисления фонда и транзакций.

## Бонус: совместимость v2

Совместимость здесь означает: ранее допустимый клиент v1 продолжает работать без изменения своих запросов и может разобрать ответы. Новая версия публикуется отдельным `/v2/`; `/v1/` не переключается скрыто. Поскольку response-схемы закрыты (`additionalProperties: false`), даже добавление response-поля не гарантированно совместимо для строгих валидаторов/SDK.

| Изменение | Для существующего клиента | Причина / стратегия |
| --- | --- | --- |
| Добавить отдельный endpoint, не меняя старые | Совместимо | Старые маршруты и поведение остаются |
| Добавить необязательный query-фильтр с прежним поведением при отсутствии | Совместимо | Старые запросы не меняются; используется новый параметр только новым клиентом |
| Добавить необязательное request-поле, не меняющее старое поведение | Совместимо в направлении старый клиент → новый сервер | Старый клиент его не отправляет; новый клиент → старый сервер несовместим из-за запрета неизвестных полей |
| Разрешить больший максимум limit, сохранив default | Совместимо для старых клиентов | Все ранее допустимые значения остаются допустимыми; новые большие значения нельзя отправлять в v1 |
| Исправить описание/добавить example без изменения семантики | Совместимо | Не меняется машинный контракт |
| Добавить поле ответа Book | Несовместимо со строгой v1-схемой | additionalProperties=false; нужен v2 либо заранее спроектированное расширяемое поле |
| Переименовать title → name или изменить тип id | Несовместимо | Ломает JSON-пути, типы и модели клиентов |
| Сделать поле/заголовок обязательным, например If-Match | Несовместимо | Старые запросы перестанут приниматься |
| Добавить обязательную Bearer JWT авторизацию | Несовместимо | Старые клиенты не отправляют Authorization; меняются ответы/доступ и scope идемпотентности |
| Поменять active так, чтобы просроченные больше не входили | Несовместимо | Меняет смысл фильтра и подсчёт активных выдач |
| Заменить offset-пагинацию обязательным cursor | Несовместимо | Меняет запрос и структуру pagination |
| Добавить значение status/error.code enum в старом ответе | Потенциально несовместимо | Генерируемые enum и исчерпывающие switch могут отвергнуть значение; нужен v2 или заранее определённый fallback |
| Изменить лимит выдач 5 → 3 либо уменьшить TTL 24h → 1h | Несовместимо | Ранее допустимые действия/повторы перестанут работать |
| Изменить границу overdue с < today на <= today | Несовместимо | Выдача со сроком сегодня внезапно станет просроченной |
| Изменить повторный возврат 200 → 409 | Несовместимо | Ломает согласованную безопасную повторяемость возврата |
| Пометить поле deprecated, не меняя его выдачу/приём | Совместимо само по себе | Это предупреждение; удаление поля позже — отдельное breaking change |

Реализован именно бонус с таблицей изменений: JWT, deprecated-поле и запуск mock не заявляются как выполненные.
