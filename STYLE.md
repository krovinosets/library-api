# STYLE — правила Library API

1. Версия входит в `servers.url`: `/v1/`. Ресурсы — существительные во множественном числе; пути и имена query-параметров — kebab-case, JSON-поля — snake_case. Не дублируем `/v1` в `paths`.
2. CRUD: POST коллекции — создание, GET — чтение, PUT — полная замена изменяемых полей, PATCH — частичное изменение, DELETE — удаление. Возврат — `POST /loans/{id}/return`, не DELETE. PUT не является upsert.
3. Создание возвращает 201 и Location; чтение/изменение/возврат — 200 с ресурсом; удаление — 204 без тела. Не маскируем ошибки под 200. Некорректный запрос — 400, отсутствующий ресурс — 404, конфликт — 409, ошибки тела/значений — 422, неподдерживаемый Content-Type — 415.
4. Request- и response-схемы раздельные. В запросах `additionalProperties: false`; PATCH непустой. `id`, `available_copies`, `registered_at`, `loaned_at`, `returned_at` генерирует/вычисляет сервер. Обновление книги/читателя не меняет серверные ID и timestamps.
5. Используем OpenAPI 3.1 и JSON Schema 2020-12: nullable через `type: [string, 'null']`, не `nullable: true`. Все типы, required, enum, format, длины и диапазоны заданы явно. `readOnly` — аннотация; запрет записи обеспечивают отдельные request-схемы. Межполевые и зависящие от времени правила документируем и проверяем на сервере.
6. Ошибки имеют один `ErrorResponse`: `error.code`, `message`, `details`, `request_id`. Не отправляем stack trace/SQL. Детали содержат `field`, `issue`, `message`; `field: null` означает запрос целиком. UI может использовать issue для уточнения причины, но не должен разбирать message.
7. Коллекции имеют `data` + `pagination` и одинаковые limit/offset (20/0 по умолчанию, limit максимум 100, offset максимум 1000000). Фильтры применяются до сортировки и пагинации; sort — одно поле с необязательным `-`, вторичный ключ всегда id ASC. Неизвестные/повторяющиеся query-параметры — 400. Пустой результат — 200, не 404.
8. Моменты времени — UTC/RFC 3339, даты — YYYY-MM-DD по UTC. Активность выдачи определяется только `returned_at = null`; overdue — активная выдача с `due_date < today_utc`. Новая due_date строго позже today_utc. Дата и время устанавливаются сервером, а не часами клиента.
9. `POST /loans` требует Idempotency-Key. Фиксируем scope, канонический fingerprint, полный replay, 409 mismatch/in-progress и TTL 24 часа. Идемпотентность не заменяет атомарность проверки наличия экземпляра/лимита читателя. Возврат повторяем без повторного изменения фонда.
10. Все операции имеют уникальный operationId, tag, summary, description, явные responses. Переиспользуем схемы/параметры/ошибки через `$ref`; examples должны соответствовать схемам. Любое изменение контракта проверяем на совместимость и отражаем в версии и документации.
